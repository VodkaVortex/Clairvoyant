  Mechanism profile of seed (never reportable as a finding): an unprivileged local user sends a generic-netlink command message; the kernel handler validates required attributes with a presence guard that uses the wrong logical connective ('&&' over negated tests instead of '||'), so the guard passes when at least one required attribute is actually absent (attrs[N] == NULL). The handler then dereferences that NULL attribute slot — passing it to nla_parse_nested_deprecated / nla_data / nla_len — causing a NULL-pointer dereference and kernel oops (local DoS; potentially worse if a missing value feeds a length/bounds computation). Transferable invariant: in netlink-backed command handlers, the attribute-presence validation must prove every attribute that is later dereferenced is non-NULL; a guard that is logically inverted, checks a different attribute than the one used, is absent entirely, or relies on a policy that does not mark the attribute required/nested-validated, leaves a NULL-or-unchecked attributes[] slot that is later treated as a valid pointer. Attacker-controlled source: userspace-supplied netlink message attribute set (presence/absence and payloads fully attacker-chosen). Missing guarantee: per-attribute non-NULL (required) validation before use. Unsafe use: dereference or nested-parse of an attributes[]/tb[] slot without a covering check. Consequence: NULL-deref oops from unprivileged input, or OOB access when the unchecked value drives sizes/indices. BRANCHES: branch1=and-presence-guard — netlink command handlers whose required-attribute guards join multiple negated presence tests with && instead of || (logical inversion), letting a missing attribute pass validation before being dereferenced; branch2=unchecked-tb-deref — handlers that dereference an attribute slot (nla_data/nla_get_*/info->attrs[N]-> or tb[N]->) for which no presence guard or policy-required covers that exact attribute, including check-one-attribute-then-use-a-different-sibling cases; branch3=nested-parse-null-arg — nla_parse_nested*/nla_validate_nested* (and analogous nested-parse helpers) invoked with a first argument taken from an optional or unvalidated attributes[] slot, so a NULL nesting attribute reaches the parser; branch4=rtnl-doit-attr-gaps — the same presence/dereference gap inside rtnetlink RTM_* doit/setlink/dumpit handlers where nlmsg_parse/nlmsg_find_attr results are indexed without per-attribute NULL checks before use.
